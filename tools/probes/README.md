# Probes

Scripts that check an assumption against test data before code depends on
it. They are not part of the test suite: they answer "is this what the data
says?" while a plan is being written, and they stay here so the answer can be
checked again by anyone.

| Script | What it checks |
|---|---|
| `check_harte_findings.py` | The behaviours the core's plan assumes, against every case in the relevant Harte files: the unstable NMOS opcodes, decimal mode on every variant, status bits 4 and 5, `JAM`, the 65C02's bus patterns, and the undefined 65C02 opcodes |
| `atari-2600/` | The Atari 2600's test suite, read from clones of its two forks at the pinned commits (task 1 of the Atari 2600 plan): `headers.sh` prints each test's header, `regs.sh` counts the registers each source names, `counts.sh` counts the tests by folder and kind, `filler.py` applies the Superchip filler rule to binaries, `pnginfo.py` decodes the reference pictures and `png_rows.py` prints a picture's rows as runs of colour. `towers_lfsr.py` checks the TIA's horizontal counter rule against Towers's table, `tia_sound.py` makes the sound table of `tia.md` section 18.5 and compares it with Korth's drawings, and `tia_palette.py` makes the palette examples of section 19.6 and checks the properties tasks 5 and 10 take tests from; each takes its source document as an argument and needs nothing beyond the standard library. `manifest-mutations.sh` plants one fault at a time in a scratch copy and shows each `SuiteManifestTests` test fail, `board-faults.py` does the same for the region, the cartridge and the boards (task 2), and `riot-faults.py` for the RIOT (task 3), listing every test case with the faults that made it fail. The results are in `docs/atari-2600/facts/suite.md`, `docs/journal/2026-10-14-the-atari-2600-fact-sheets.md` `docs/journal/2026-10-14-the-atari-2600-cartridge-and-boards.md` and `docs/journal/2026-10-14-the-atari-2600-riot.md` |
| `atari-2600/bus-faults.py` | The Atari 2600 plan's task 4 fault pass: one fault at a time in the bus, the machine, the TIA's first version and the state reports, in a scratch copy, with the test files each fault fails or SURVIVED; its patterns were ported as later tasks rewrote the code. Results in `docs/journal/2026-10-14-the-atari-2600-bus-and-machine.md` |
| `atari-2600/tia-line-faults.py` | Task 5's fault pass, the same way, for the TIA's line, the playfield, the palette, the frame, the order inside a cycle and the state reports. Results in `docs/journal/2026-10-14-the-atari-2600-tias-line.md` |
| `atari-2600/cycle-split.py` | Task 5, step 3: builds the machine with each of the four splits of a cycle's colour clocks around its access and prints which trusted self-tests and `CycleOrderTests` cases each passes. Results in `docs/journal/2026-10-14-the-atari-2600-tias-line.md` |
| `atari-2600/tia-object-faults.py` | Task 6's fault pass, for the objects, their position counters, priority, score mode and the collision latches. Results in `docs/journal/2026-10-14-the-atari-2600-tias-objects.md` |
| `atari-2600/tia-motion-faults.py` | Task 7's fault pass, for HMOVE and the motion clocks, the screenshot runner's partition rule and PNG reader, and the state reports. Results in `docs/journal/2026-10-14-the-atari-2600-hmove.md` |
| `atari-2600/input-faults.py` | Task 9's fault pass, for the controllers, the TIA's fire buttons, latch and paddle ports, and the RIOT's port A. Results in `docs/journal/2026-10-14-the-atari-2600-input.md` |
| `atari-2600/sound-faults.py` | Task 10's fault pass, for the sound, the sample buffer and the machine's catch-up. Results in `docs/journal/2026-10-14-the-atari-2600-sound.md` |
| `atari-2600/suite-record-faults.py` | Task 11's fault pass, for the recorded outcomes in `machines/atari-2600/suite-outcomes.json` and the suite's tables. Results in `docs/journal/2026-10-14-the-atari-2600-suite-in-full.md` |
| `atari-2600/boot-faults.py` | Task 12's fault pass, for the bundled game's files, the recorded frames, the boot check's switches and the machine. Results in `docs/journal/2026-10-14-the-atari-2600-bundled-game.md` |
| `atari-2600/panel-faults.py` | Task 13's fault pass, for the page's parts and the WebAssembly host's source, run against the NES's and the Atari 2600's panel tests with node. Results in `docs/journal/2026-10-14-the-atari-2600-panel.md` |
| `atari-2600/page-faults.py` | Task 14's fault pass, for the page and what it is built from, run against the site's tests after a build in the scratch copy. Results in `docs/journal/2026-10-14-the-atari-2600-page.md` |
| `atari-2600/mutation-pass.py` | Task 15's mutation pass: the plan's mutations, each planted alone in a scratch copy of the committed head, with the tests each fails or SURVIVED. Results in `docs/journal/2026-10-14-the-atari-2600-mutation-pass.md` |
| `bbc_models_mutations.py` | That the BBC Micro models' tests notice each of the faults task 10 of the models plan lists, and more: plants one at a time in the models' data, modules, tools, credits, the page's wiring, the browser check's node-testable parts and the machine's counters, runs the site suite (after a build), the tools' pytest and, for C#, the BBC Micro's test project, reports what failed and puts the files back. Run it on a scratch worktree with `--root`; the results are in `docs/journal/2026-10-04-the-bbc-micro-models.md`, "Task 10" |
| `electron_mutations.py` | That the Electron's tests notice each of the faults task 15 of the Electron plan lists: plants one at a time, runs the Electron test project (and the site's key test where the page's copy of the matrix changes), reports what failed and puts the files back. Run it in a scratch worktree; the results are in `docs/journal/2026-10-13-the-electron-mutation-pass.md` |
| `kim1_serial_routines.py` | The KIM-1 monitor's teletype routines, disassembled from the hash-checked ROM in `roms/kim-1/`: reset's speed measurement, GETCH, OUTCH, the delay loops and the commands, each labelled |
| `kim1_teletype_mutations.py` | Plants 22 faults, one at a time, in the KIM-1 teletype (the machine) and its page, runs the tests that should notice, puts each file back, and reports which tests failed or that the fault survived. Unlike the others it runs tests and takes minutes; it is how the journal's mutation tables were made |

Run from the repository root with Python 3 and no other dependencies. Data is
downloaded from a pinned commit into `.testdata/`, which git ignores.
