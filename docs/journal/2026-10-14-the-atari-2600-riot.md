# 14 October 2026: the Atari 2600's RIOT

Task 3 of [the Atari 2600 plan](../superpowers/plans/2026-10-14-atari-2600.md): `Riot6532`, the 6532 RIOT, chip alone, built from [`riot.md`](../atari-2600/facts/riot.md). Nothing runs a program yet: the bus is task 4, and the suite's `riot/` tests run from there, so none is claimed here.

## What was built

`src/Dbhq.Machines.Atari2600/Riot6532.cs`, with the plan's interface: 128 bytes of RAM, ports A and B with their direction registers, the interval timer, the PA7 edge detect, the flag register and the chip's own IRQ pin, which goes nowhere on the 2600. `ReadRegister` is the CPU's read with its side effects; `PeekRegister` returns the same byte with none, for the bus's `Peek`. The chip has no clock of its own: the bus calls `Tick` once at the start of every CPU cycle, halted or not, then makes the cycle's access. So a timer write's cycle is the sheet's cycle 0 and the count first falls on cycle 1. The register methods decode A0 to A4 only and the RAM methods A0 to A6, so the bus can pass any address of the chip's half, mirrors included.

It is a new class, as the spec decided. The KIM-1's `Rriot6530` was read for its shape (the timer's countdown and its "set this cycle" guard came out the same way) and nothing was taken from it or changed in it.

## The 6530 against the 6532, row by row

`riot.md` section 1 checked the spec's table against the data sheets. As built:

| Row | Verdict | In the code |
|---|---|---|
| Memory | Confirmed: no ROM, 128 bytes of RAM | `RamSize`, A0 to A6 |
| Selecting RAM or I/O | 6530 corrected (a mask-programmed decode of RS0 and A6 to A9), 6532 confirmed: RS, which the 2600 wires to A9 | The bus's, in task 4; the chip has separate RAM and register methods |
| Interrupt output | Confirmed: a pin of its own, not connected | `Irq`, for the chip's tests only |
| PA7 edge detect | Confirmed, with detail: polarity and enable come from the write's address (A0 and A1), the data is ignored, and the flag is set whether or not the enable is on | `WriteRegister` with A2 high and A4 low |
| Reading the flags | Confirmed, with detail: bit 7 the timer, bit 6 the edge, bits 5 to 0 zero; reading clears the edge flag only; the timer flag is cleared by a timer read or write | `ReadRegister` with A2 and A0 high |
| Timer | Confirmed, and the open point settled: the flag is set on cycle D x N + 1, and a read on that very cycle returns `$FF` and leaves the flag set | `Tick` and `ReadRegister` |

## Decisions

- **`Tick` runs before the cycle's access**, as the KIM-1's does, over after it. The sheet's cycle numbers then fall out with no offset: the write is cycle 0 and its own cycle does not count. Task 4's `Cycle` calls it in that order.
- **The edge detect runs when the pin can change** (an ORA or DDRA write, or a new `PortAInput`), over comparing the pin on every `Tick`. A flag set on the change is there for a read on any later cycle, which is all the suite needs, and `Tick`, which runs every cycle, does no work for the ports. When the real flag becomes visible is not stated (`riot.md` section 12 item 5) `[guessing - verify]`.
- **A port A output pin is the AND of ORA and what drives it**, so an output at 1 reads 0 while its switch is closed. This is `riot.md` section 5's inference, marked `[guessing - verify]` there and in the code; task 9 decides it for the joysticks and may change it. Port B's outputs are push-pull and read ORB, which the sheet does state.
- **The inputs default to `$FF`**, nothing pressed and every pull-up high, so the chip alone reads as a 2600 with nothing plugged in. Task 9's controllers set them.
- **The power-on state.** RES's part as the sheet gives it (the I/O registers zeroed, both interrupts off, the negative edge armed). The rest is the model's choice, so runs repeat: the RAM clear, both flags clear, and the count at `$00` at divide by 1, so the first cycle passes zero and the timer free-runs, as the real one has since its own reset ended, before the CPU's. Chosen over a count at `$00` waiting at divide by 1024, which a real chip would not be doing by the time the program starts. In `docs/known-differences.md`.
- **The constructor powers the chip on**, so a new chip and a powered-on one are the same.

## What is guessed, and marked

Each is `[guessing - verify]` in a comment in `Riot6532.cs` and in `docs/known-differences.md`:

1. After a read ends the free run, the first fall comes a whole divider after the read (`riot.md` section 12 item 1).
2. A read on the cycle the flag is set leaves the free run going, as it leaves the flag (section 12 item 2).
3. In the free run, when the count wraps past `$00` again, a read on that cycle clears the flag: only the first pass of zero is "the interrupt occurring". No source reaches this; the KIM-1's `Rriot6530` protects a read on every wrap, which is the other reading.
4. A port A output at 1 reads 0 against a closed switch (section 5).
5. The edge flag is seen from the cycle the pin changes (section 12 item 5).

## The tests, test first

`tests/Dbhq.Machines.Atari2600.Tests/Riot6532Tests.cs`, each test named after the section or worked example it is taken from: RAM and its address-identity march (section 4); the decode's mirrors and A4 on a write (worked example 1); port A's output register (worked example 2) and port B's (worked example 3); the timer at each divider (worked example 4), the count on every cycle by section 6's rule, the data sheet's own case of 52 at divide by 8, a write of 0, the flag's clearing rules (worked example 5), the read on the cycle it passes zero (worked example 6, the suite's `timer-underflow-read`), the suite's `timer-vblank-spin` counts at one-cycle resolution (worked example 7); the enables and the IRQ pin (worked example 8); the PA7 edges (worked example 9), arming that sets nothing, the ignored data, and edges from the joystick and from DDRA; power on; and `PeekRegister` against a twin chip that is never peeked.

The file was written before the chip: the first build failed to compile with `CS0246`, `Riot6532` not found. With the chip written, every test passed on the first run. On 14 October 2026 `dotnet test -c Release tests/Dbhq.Machines.Atari2600.Tests --filter "FullyQualifiedName~Riot6532Tests"` passed 43 test cases, and the whole project (`dotnet test -c Release tests/Dbhq.Machines.Atari2600.Tests`) passed 249. `dotnet build -c Release` of the solution gave no warnings.
