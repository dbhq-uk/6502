# BBC Micro Model B: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Acorn BBC Micro Model B on the core: it boots MOS 1.20 to the BBC BASIC prompt in all eight screen modes, runs a BASIC program, saves a file to a disc image through DFS and loads it back, and runs in the browser at 6502.dbhq.uk, as the design in [`../specs/2026-10-02-bbc-micro-design.md`](../specs/2026-10-02-bbc-micro-design.md) says.

**Architecture:** A new library `Dbhq.Machines.BbcMicro` on the `Nmos6502` core. A `BbcBus` implements `IBus`; every `Read` or `Write` is one 2 MHz CPU cycle and ticks every other chip, and an access to a 1 MHz device first ticks the stretch cycles. Each chip is one class in its own file, tested alone, written from the datasheets and the fact sheets in [`docs/bbc-micro/facts/`](../../bbc-micro/facts/README.md), never from another emulator's code. A shared browser host (`machine-host.js`) is extracted from the KIM-1's page script, and both machines run on it.

**Tech Stack:** C# on .NET 10, xUnit 2.9.3 (the versions the KIM-1 tests use), .NET WebAssembly compiled ahead of time for the browser, plain JavaScript modules and an `AudioWorklet` for the page, Astro for the site, Playwright for the real-browser check.

**This plan has NOT been pre-run the way the stage 1 plan was.** The BBC's chips are thousands of lines, so their code is not written into the plan. Each task states its interfaces, the facts it is built from, and the exact test assertions; the implementer writes the tests first and the code to pass them, and a reviewer gates each task. What is proven early instead is the risky part: task 5 boots the real OS ROM headless and task 6 measures the speed in a browser. The design (section "Proof") says this.

## Global Constraints

- **Every bus access is one cycle.** `BbcBus.Read` and `Write` are one 2 MHz CPU cycle each, and they tick the other chips. A slow device first ticks its stretch cycles, then does the access. (`AGENTS.md` rule 1; design section "Parts".)
- **The core knows no machine.** Nothing under `src/Dbhq.Cpu6502/` names the BBC Micro. (Rule 2.)
- **No code from another emulator.** jsbeeb and B-em are GPL and this repository is MIT. Chips are written from datasheets and the fact sheets. Only the ROMs and the CC0 teletext glyph table are taken from outside. (Design section "Where the code comes from".)
- **System ROMs are committed under `roms/bbc-micro/`**, with where they came from and what is known of their rights in `roms/README.md`, checked against a SHA-256 pinned in `Pins.cs` every time they are read. (Rules 3 and 4.)
- **Nothing depends on a third party's server.** `site/tests/mirrors.test.mjs` fails on any fetch from outside `dbhq-uk`. No test needs the network.
- **No figure describing the project as it stands is typed by hand.** The home page count and every pass count come from the registry and the test results. (Rule 5.)
- **Document as you go.** Each task ends by adding to that day's journal entry in `docs/journal/`: what was built, what the tests showed, what surprised, and any decision with what it was chosen over. A difference from a reference also goes in `docs/known-differences.md`. (Rule 6.)
- **The page says what is not modelled:** the 6850 serial port, the ADC and joystick port, the Tube, the cassette interface, the printer port and the 1 MHz bus. (Design, "What is left out".)
- **Namespace `Dbhq.Machines.BbcMicro`**; projects `src/Dbhq.Machines.BbcMicro/`, `src/Dbhq.Machines.BbcMicro.Wasm/`, `tests/Dbhq.Machines.BbcMicro.Tests/`; all in `6502.slnx`.
- **Warnings are errors** (`Directory.Build.props`: `net10.0`, nullable, implicit usings, `TreatWarningsAsErrors`).
- **British English, and no em or en dashes** in code, comments, docs and the site. CI checks the dashes.
- **The site's copy rules hold:** headings carry no trailing full stop, and `site/tests/` has its own content checks, which must pass.
- **Git:** all work is on branch `feat/bbc-micro`, one commit per task with a conventional-commit message, pushed after each. A draft pull request is opened after task 1 so `Validate` runs on every push, and marked ready after task 14. It is merged only when `Validate` is green and Dan says so, because merging deploys and changes the live count. The 3D models are a separate branch and a separate plan.
- **Stay on the branch.** Never switch, create or move to another branch or worktree except as this plan says.

### Task 2: The bus, the memory map and the 1 MHz stretch

**Files:**
- Create: `src/Dbhq.Machines.BbcMicro/BbcBus.cs`
- Test: `tests/Dbhq.Machines.BbcMicro.Tests/BbcBusTests.cs`

**Interfaces:**
- Consumes: `BbcRoms` (task 1), `IBus` (core).
- Produces:
  ```csharp
  public sealed class BbcBus : IBus
  {
      public BbcBus(BbcRoms roms);
      public long Cycles { get; }                 // 2 MHz CPU cycles since power on, stretch cycles included
      public int RomSlot { get; }                 // the paged ROM latch, 0 to 15
      public byte Read(ushort address);
      public void Write(ushort address, byte value);
      public byte Peek(ushort address);           // no cycle, no side effect; for tests and debuggers
      public void PokeRam(ushort address, byte value);   // for tests: loads RAM without a cycle
      protected/internal virtual void Tick();     // one CPU cycle for every other chip; empty until later tasks
      internal Func<ushort, bool> /* none */      // no hooks yet: later tasks add device fields
  }
  ```
  Later tasks add the chips as properties and call them from `Tick` and from the SHEILA decode; keep SHEILA decoding in one method `ReadSheila(int offset)` / `WriteSheila(int offset, byte value)` so each task adds a `case`.

**What it must do (`bus.md` s1 and s2):**
- `$0000-$7FFF` RAM, 32 KB, no aliasing at `$4000` (the OS tells a Model A by aliasing). Writes to ROM are ignored. `$8000-$BFFF` is the paged ROM chosen by `RomSlot`: slot 15 reads BASIC, slot 14 reads DFS, every other slot reads the high byte of the address (an empty slot: the last value on the bus; `bus.md` s6 lists this as not established, take the rule in `bus.md` s1d for fast absent devices). `$C000-$FBFF` and `$FF00-$FFFF` read the OS ROM. `$FC00-$FEFF` is I/O, never ROM.
- The ROM latch: any write to `$FE30-$FE3F` sets `RomSlot` to the low four bits. Power-on value 0 (not established; the OS writes it before the first read of `$8000`).
- Absent-device reads (the OS depends on them): FRED and JIM (`$FC00-$FDFF`) read `$FF`; an absent fast SHEILA device reads the high byte of the address (`$FE`); an absent slow SHEILA device reads `$00`. Absent now means every SHEILA device, until the later tasks add them. The unmapped ADC at `$FEC0` must read with bit 6 clear (`via.md` s2.5), which the `$00` rule gives for a slow device; check the ADC is slow in `bus.md` s2a (it is).
- The stretch (`bus.md` s2b): the slow ranges are `$FC00-$FEFF` minus the fast devices; the fast SHEILA devices are the video ULA `$FE20-$FE2F`, the ROM latch `$FE30-$FE3F`, the 8271 `$FE80-$FE9F`, the ADLC `$FEA0-$FEBF` and the Tube `$FEE0-$FEFF`; `$FE00-$FE1F` is slow (the sheet treats `$FE18-$FE1F` as not established; make it slow). For a bus cycle at a slow address, with `T` = `Cycles` before the cycle: `wait = 1 + (T & 1)` extra cycles, each calling `Tick()`, then the access cycle. Judge every bus cycle separately by its own address, including the CPU's dummy reads and read-modify-write double writes.

- [ ] **Step 1: Write the failing tests** (`BbcBusTests.cs`). Build the bus from the real ROMs (`RepoPaths.ReadChecked`). Assert:
  - RAM read-back at `$0000` and `$7FFF`; `$4000` does not alias `$0000`.
  - A write to `$C000` leaves it unchanged.
  - `Peek(0xFFFC)` is `0xCD` and `Peek(0xFFFD)` is `0xD9`; `Peek(0xC000)` is `0x?` the first byte of `os.rom`: compare with `RepoPaths.ReadChecked(...)[0]` rather than typing a value.
  - ROM latch: write `$0F` to `$FE30`, `Peek(0x8009)` is `'B'` (the start of the title "BASIC" at `$8009`); write `$0E` to `$FE3F`, `Peek(0x8009)` is the DFS header's byte; write `$03`, an empty slot reads `0x80` (the high byte). Check the DFS header byte against `RepoPaths.ReadChecked(DFS)[9]`.
  - Absent devices: `Read(0xFC00)` and `Read(0xFD00)` are `0xFF`; `Read(0xFEA0)` is `0xFE`; `Read(0xFEC0)` is `0x00`; `Read(0xFEE0) & 1` is `0` (the Tube probe).
  - Stretch parity. A subclass or a test counter records `Tick()` calls. From `Cycles` even, a read of `$FE40` takes 2 cycles in total (`Cycles` advances by 2); from `Cycles` odd it takes 3. Two slow reads in a row from even `Cycles` cost 2 then 2. A RAM read costs 1. A fast SHEILA read (`$FE20` write) costs 1. A write to a slow address costs the same as a read.
  - Dummy reads count: drive the bus the way `STA $FE40,X` does (read at the unfixed address then the write) and assert both cycles are judged by their own address.

### Task 3: The 6522 VIA, chip alone

**Files:**

  ```csharp
  public class Via6522
  {
      public void Reset();                         // register state after /RES (via.md s1.2)
      public void Tick();                          // one 1 MHz cycle; call at the START of the cycle
      public byte Read(int register);              // 0 to 15, during the current cycle
      public void Write(int register, byte value);
      public bool Irq { get; }                     // the IRQ_N line, true when asserted
      public byte PortAInput { get; set; }         // what the outside drives on PA7..0
      public byte PortBInput { get; set; }         // likewise PB
      public byte PortAPins { get; }               // the level on each pin: output bits from ORA, input bits from PortAInput
      public byte PortBPins { get; }               // as above; PB7 follows the timer 1 output when ACR7 is set (via.md s1.3)
      public void SetCa1(bool level); SetCa2; SetCb1; SetCb2;
      public bool Ca2Out { get; } bool Cb2Out { get; }
      public event Action? PortAWritten, PortBWritten;   // raised after a write to ORA/ORB/DDRA/DDRB
  }
  ```
  `SystemVia` and `UserVia` (task 4) subclass or wrap it.

**Built from:** `via.md` s1 in full: the 16 registers (1.1), reset (1.2), port reads (1.3), timer 1 (1.4), timer 2 (1.5), IFR and IER (1.6), the control lines (1.7), ACR and the shift register (1.8), the visibility rule (1.9). The shift register is needed only in mode 2 (shift in under the system clock), to set IFR bit 2 about 19 cycles after an SR read; `via.md` marks that number `[guessing - verify]`, so implement mode 2 with a named constant `ShiftMode2Cycles = 19` and say in the journal that DFS 1.20 only needs the flag to appear (`disc.md` s2). Other shift modes may set no flag and are listed in `docs/known-differences.md`.

- [ ] **Step 1: Write the failing tests**, one per worked example in `via.md` s1.10 (16 of them), each named after its number and what it shows, with W the write cycle and every read at the cycle the sheet gives. Concretely, in test helpers `Write(reg, v)` runs `Tick()` then `Write`, and `ReadAt(k)` runs `k` further `Tick()`s then `Read`:
  1. One-shot, N=4 (T1C-L `$04`, then T1C-H `$00`): T1C-L reads 4,3,2,1,0 at W+1..W+5 and `$FF` at W+6; IFR is `$00` through W+5 and `$C0` from W+6 (IER `$C0`); IRQ asserted from W+6.
  2. N=0: T1C-L reads 0 at W+1, `$FF` at W+2; IFR6 set in W+2.
  3. Free-run (ACR `$40`), N=4: flag cycles W+6, W+12, W+18; T1C-L per period 4,3,2,1,0,`$FF`,4; reading T1C-L in W+7 clears the flag and the next flag is still W+12.
  4. ACR `$C0`, DDRB7=1, N=4: PB7 reads 0 from W+1, 1 from W+6, 0 again from W+12, alternating each 6 cycles.
  5. ACR `$80`, N=4: PB7 0 from W+1 to W+5, 1 from W+6 and stays 1.
  6. The OS tick: ACR `$40`, latch `$270E`: the flag recurs every exactly 10000 cycles.
  7. T2 one-shot, T2L-L=3, T2C-H=0: T2C-L reads 3,2,1,0 at W+1..W+4, `$FF` at W+5, `$FE` at W+6 (no reload); IFR5 set once.
  8. ACR `$60` (T2 pulse count), PB6 held high, T2C-H written: T2 never counts, IFR5 never sets.
  9. Coincident acknowledge: example 1 with a T1C-L read in W+6: IFR6 is still set after it; IRQ asserted from W+7; a read in W+7 clears it.
  10. IFR write `$40` clears IFR6 and IFR reads `$00` with IER `$C0` (bit 7 follows the flags).
  11. IER=0, T1 flag set: IFR reads `$40`; writing `$C0` to IER makes IFR read `$C0`.
  12. After reset IER reads `$80`; writing `$7F` leaves `$80`; writing `$F2` reads `$F2`.
  13. After reset ORB, ORA and both DDRs read 0; port B with inputs high reads `$FF`.
  14. DDRB `$0F`, ORB `$0A`, PB4-7 pins high: ORB reads `$FA`.
  15. DDRA `$7F`, ORA `$35`, PA7 pin driven high: IRA reads `$B5`.
  16. A T1L-H write after one-shot expiry clears IFR6.
  Plus: the control-line edges (CA1 negative edge with PCR `$04` sets IFR1; CA2 positive edge sets IFR0 as the keyboard needs, `via.md` s1.7), IFR/IER bit 7 rules, and `Reset` leaving IER at `$80`.
